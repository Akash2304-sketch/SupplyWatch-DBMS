# SupplyWatch - Ready-to-Implement Project

This package contains the Next.js frontend, Express API backend, MongoDB document/vector-search scripts, and the user's original MySQL SQL scripts.

## Architecture
- MySQL: source of truth for suppliers, products, inventory, purchase orders, deliveries and reporting views.
- MongoDB: supplier-risk notes and searchable unstructured observations. Vector search is an optional Atlas capability.
- Next.js: dashboard and management UI.
- Express: API connecting the frontend to MySQL and MongoDB.

## Requirements
- Node.js 20.9+
- MySQL 8.0+
- MongoDB local instance OR MongoDB Atlas
- VS Code

## 1. MySQL
Run the SQL scripts in `database/` in this order:
1. `01_schema.sql`
2. `02_seed_data.sql`
3. `03_views.sql`
4. `04_triggers.sql`
5. `05_procedures.sql`

Run `06_reports_and_tests.sql` selectively. It contains stored-procedure calls that modify demo data.

## 2. Backend
Open a terminal in `backend/`:
```powershell
npm.cmd install
copy .env.example .env
```
Edit `.env` with your MySQL and MongoDB connection details, then:
```powershell
npm.cmd run dev
```
API runs at http://localhost:5001

## 3. Frontend
Open another terminal in `frontend/`:
```powershell
npm.cmd install
copy .env.local.example .env.local
npm.cmd run dev
```
Open http://localhost:3000

If you already generated a Next.js app, you can replace its `src/app` folder and `package.json` with the versions in this package. The package is configured for Next.js App Router and Tailwind CSS.

## 4. MongoDB and Vector Search
The backend writes supplier risk observations to MongoDB collection `supplier_risk_notes`.
For semantic vector search, use MongoDB Atlas and create a Vector Search index named `supplier_risk_vector_index` using `mongodb/vector-index.json`. Vector search requires embeddings generated by an embedding model. The project deliberately does not invent embeddings; add actual embedding vectors before running semantic search.

## Notes
- The first frontend build includes a dashboard and pages for inventory, suppliers, purchase orders and risk notes.
- The UI displays database-backed values when the backend is configured.
- If the API is unavailable, the frontend shows an explicit connection warning rather than pretending demo values are live.
- Your uploaded SQL seed data is fictional demonstration data.
